工作大纲 · 四种思维导图样式

数据用的是同一个项目的真实结构（项目 → 阶段 → 任务 → 子任务），方便横向比较。 每张图下面写了这种样式的手感与代价，选一个方向我就按它实现。

A. 双侧放射式 XMind / MindManager 的经典样子

中心在中间左右分支曲线连接 手感：最像"思维导图"，看整体结构很舒服。 代价：节点一多就往两边长，宽屏才够用；编辑时要处理左右两侧的排版方向。

B. 水平树（左根右叶） ProcessOn / 百度脑图 / 幕布导图

根在左侧逐级向右可折叠 手感：最适合"工作大纲"—— 读起来像一份层层展开的计划书，和任务列表能一一对应。 代价：深层节点会往右跑，需要横向滚动或折叠。

C. 极简大纲树 markmap（Markdown 直接变导图）

细线无边框像文档 手感：最干净，节点就是文字，靠缩进+细线表达层级；适合"每天盯着看"的工作大纲。 代价：状态、优先级、负责人这些信息要靠小色点/小字补充，不如卡片直观。

D. 自上而下的树（组织架构式） Org chart / 甘特大纲

根在上正交连线层级清楚 手感：层级关系一眼看懂，适合"阶段 → 任务"这种不深但很宽的结构。 代价：宽度有限，任务多时会横向挤；子任务多时容易变成一大排。
